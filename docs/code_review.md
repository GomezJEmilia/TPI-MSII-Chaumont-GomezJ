# Checklist de code review

- [ ] La versión inicial se conserva para poder comparar el antes y el después.
- [ ] La versión refactorizada conserva las operaciones principales del sistema.
- [ ] Las reglas de negocio están separadas de la consola y del almacenamiento.
- [ ] Las entradas inválidas y las transiciones no permitidas se rechazan sin modificar los datos.
- [ ] Las pruebas comparativas pasan y muestran los mismos resultados para los casos válidos.
- [ ] El README explica correctamente cómo ejecutar y probar el proyecto.

**Criterio de aprobación:** se aprueba cuando todos los puntos aplicables cumplen. Si alguno falla, se pide corregirlo y se vuelve a revisar.
